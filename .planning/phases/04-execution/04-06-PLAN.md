    `gates.test.ts`, `node:test` + `node:assert/strict`, pure — every gate takes text and
    returns a decision, so none of them needs git.
    - **DELV-04:** a branch equal to `defaultBranch` is refused with a named error. Assert
      the error type, not just that it threw, because the caller distinguishes a refusal
      from a failure. Also assert the comparison is exact — a branch named
      `main-something` is not refused.
    - **DELV-09:** one test per secret pattern, each with a realistic-shaped fake value
      embedded in a plausible diff line, each blocking. Assert the report names the file
      and the line number, because "a secret was found" with no location is a report the
      operator cannot act on.
    - A diff adding a `.env` file is blocked even when its contents match no pattern —
      environment files are named in DELV-09 alongside secrets and are blocked by path.
    - A diff **removing** a line that contains a secret does not block. A removal is the
      agent cleaning up, and blocking it would make the guardrail punish the fix.
    - A file whose path is in the CI set sets the flag and does **not** block; a file
      matching none sets neither. The flag and the block are different dispositions and
      conflating them either blocks legitimate CI work or lets a secret through.
    - `.claude/settings.json` sets the CI flag, for the same reason.
    - Path matching is on path segments, not substrings: a file named
      `docs/circleci-notes.md` does not set the flag, and `.github/workflows/ci.yml` does.
    - `runPrePushGates` composes all three and returns a single result carrying the
      refusal, the block, and the flag, so the caller has one thing to check rather than
      three it might forget one of.
  </behavior>

    Complete `src/execution/gates.ts` around the default-branch refusal plan 04-01 shipped.
    Export `assertPushAllowed`, `findSecrets(diff)`, `touchesCiPaths(files)`, and
    `runPrePushGates(o)` composing all three.

    Keep every gate a **pure function over text**. They run no git commands; the caller
    collects the diff and the changed-file list and passes them in. That is what makes them
    exhaustively testable with no repository, and — more importantly — it is what makes it
    structurally impossible for a gate to end up downstream of the push it gates.

    **`assertPushAllowed` (DELV-04, D-13).** Exact string comparison against the mapping's
    default branch, throwing a distinctly-named refusal. This is a hard precondition, not
    a warning, because a push to the default branch cannot be undone and GitHub branch
    protection — the control that actually holds — may or may not be configured on any
    given mapped repo.

    **`findSecrets` (DELV-09).** Scan only **added** lines: in a unified diff those begin
    with a single `+` and are not the `+++` file header. Return every hit with its file
    path, line number and the matched pattern name — never the matched value itself, because
    a report that echoes the secret writes it to a second place.

    Also block by path: a diff that adds or modifies a `.env` file, or a file matching the
    usual environment-file shapes, is blocked regardless of contents.

    Comment the honest limit: this is a guardrail against an agent committing a fixture, not
    a defence against an adversary. A fixed regex set will miss things. It is stated as such
    in the research and stating it in the code is what stops someone later treating a pass
    as proof.

    **`touchesCiPaths` (DELV-08).** Match on path **segments**, so `.circleci/` matches the
    directory and not a filename that merely contains the string. Return the matching paths,
    not a boolean — the PR body names them and so does the terminal comment. Flag; never
    block. Note in a comment that a push touching workflow files is separately rejected by
    GitHub without a `workflow` token scope, so this flag is about making the human look,
    not about preventing the write.

    **`runPrePushGates`** returns `{ refusal?, block?, ciPaths[] }`. One composed call with
    one result is what makes "did the caller check all three" a question with one answer.

    **`src/execution/pr-body.ts` (DELV-03).** Export `renderPrBody(o): string`, pure.

    **what I did not do** section; and the path to the run log.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Agent-authored diff -> GitHub remote | The worker pushes code it did not author to a remote the operator owns; this is the only irreversible write in the milestone |
| Agent-authored summary -> PR body -> human reviewer | Text produced by a process steered in part by attacker-influenceable ticket text is rendered into a page a human reads and trusts |
| Linear issue title -> `gh` argv and GitHub page | Untrusted text crosses into a subprocess argument and a rendered page |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-33 | Information Disclosure | gates.ts / deliver.ts | critical | mitigate | `findSecrets` scans added diff lines and environment-file paths, and a hit returns before the push is constructed; the report names file and line but never echoes the matched value |

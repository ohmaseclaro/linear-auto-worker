  <name>Task 1: Tunnel module with a checked URL and a sanitised failure path</name>
  <files>src/ingress/tunnel.ts, test/ingress/tunnel.test.ts</files>

  </read_first>
  <behavior>
    - NGROK_AUTHTOKEN absent from the environment: throws before any network call, and the
      message names `~/.linear-auto-worker/.env`.
    - Connect rejects with a message containing `ERR_NGROK_4018`: throws a message carrying
      that code and nothing else from the original error.
    - Connect rejects with a message containing `ERR_NGROK_105` and an echoed token: the
      thrown message contains neither the token nor the original error object.
    - `listener.url()` returns null: the listener is closed and boot fails.
    - Two listeners present after connect: throws, naming the observed count.
    - Happy path: returns `{ listener, url }` with a non-empty string url.
    - `closeTunnel(listener)` invokes `listener.close()`.
    - `installTunnelShutdownHooks()` registers SIGINT and SIGTERM handlers.
  </behavior>
  <action>
    Write `src/ingress/tunnel.ts` exporting `openTunnel(port: number): Promise<{ listener: Listener; url: string }>`,
    `closeTunnel(listener: Listener): Promise<void>`, and `installTunnelShutdownHooks(): void`.

    Sequence inside `openTunnel`, in this order and no other:

    1. Read `process.env.NGROK_AUTHTOKEN` and throw immediately when it is falsy, with a
       message that names `~/.linear-auto-worker/.env` and the setup wizard. Per T25 an
       unset variable and a revoked account produce the identical `ERR_NGROK_4018`
       failure, so the SDK cannot tell the operator which one they are looking at — this
       pre-check is the only place that message can come from (TUN-03).
    2. Call `ngrok.connect({ addr: port, authtoken_from_env: true })`. Pass no domain key
       whatsoever; its absence is what makes the URL ephemeral, which is locked by D-01.
       Per T10 the SDK reads neither the bare environment variable nor the macOS agent
       YAML on its own, so `authtoken_from_env: true` is mandatory.
    3. Wrap that call in try/catch. In the catch, extract `/ERR_NGROK_(\d+)/` from
       `String((e as Error).message)` and throw a new Error carrying only the extracted
       code plus remediation text. Do not attach, re-throw, or log the caught error: per
       T24 the malformed-token failure echoes the operator's authtoken inside its own
       message, so any path that forwards that object writes a live credential to disk.
       Per T25 the error's `code` property is `GenericFailure` for every ngrok failure and
       cannot discriminate anything — the message regex is the only working branch.
    4. Read `listener.url()` into a local. Per T19 its type is `string | null`; unchecked,
       the null flows into template interpolation and plan 03-02 registers a URL Linear
       accepts as a string and never delivers to, producing a daemon that boots clean,
       logs healthy and receives nothing. When it is falsy: close the listener, then throw
       a fatal boot error refusing to register an unreachable webhook.
    5. Await `ngrok.listeners()` and throw when the length is not exactly 1, naming the
       observed count. This converts TUN-01 from a code-review claim into a runtime
       assertion.

    `closeTunnel` is a one-line delegate to `listener.close()`. `installTunnelShutdownHooks`
    registers `process.once` handlers for SIGINT and SIGTERM that call `ngrok.kill()` and
    then exit. Register nothing at module scope — Phase 7 owns daemon lifecycle and calls
    this explicitly; module-scope signal handlers fire in every test run and every import.
    Record `installTunnelShutdownHooks` in `03-SUMMARY.md` under
    `Contract additions requested` so Phase 7 wires it.

    TUN-02's crash and restart cases need no code: the native session is bound to the OS
    process, so an orphan is structurally impossible. State that in a comment rather than
    building PID or lockfile machinery.

    Write `test/ingress/tunnel.test.ts` against a hand-written fake ngrok module covering
    every case in the behavior block above. Use `node:test` and `node:assert/strict`
    (01-CONTEXT D-12). Do not run it — the milestone integration gate runs it.

    Keep every trap reference in a comment that occupies its own line; the verify gate
    strips whole-line comments but not trailing ones.

  <name>Task 1: Loop-prevention layers 1-3 as named pure predicates</name>
  <files>src/ingress/guards.ts</files>
  <behavior>
    - actor is null: drop, guard `actor:null-untrusted`.
    - actor is undefined: drop, same guard.
    - actor type is user and id equals the bot id: drop, guard `actor:self`.
    - actor type is user and id is someone else: pass.
    - actor type is integration with the bot id: passes layer 1 (the discriminant does not
      match) and must still be caught by a later layer — this is the case assumption A6
      exists for, and the returned actorType is how it becomes visible.
    - Comment payload whose body carries the bot marker prefix: drop, guard
      `marker:bot-authored`, regardless of actor.
    - Comment payload with an ordinary body: pass.
    - Issue payload: the marker layer does not apply and does not throw.
    - noteSelfWrite("Comment", "c1") then an event for Comment c1 inside the window: drop,
      guard `suppression:self-write`.
    - The same event after the window has elapsed: pass.
    - Each drop increments the counter under its own guard name.
  </behavior>
  <action>
    Write `src/ingress/guards.ts` exporting:

    - `SELF_WRITE_SUPPRESSION_MS = 90_000`
    - `noteSelfWrite(entityType: string, entityId: string): void`
    - `selfEventGuards(payload, botUserId: string): { drop: boolean; guard?: string; actorType?: string }`
    - `selfEventDropCounts: Readonly<Record<string, number>>` and
      `incSelfEventDrop(guard: string): void`

    Layer 1 — actor identity (D-08). Read `payload.actor` into a local first. When it is
    falsy, return a drop with guard `actor:null-untrusted`: a missing actor is not evidence
    an event came from a human, and D-08 locks it as untrusted. Only then compare — when
    the actor type is the string `user` and its id equals `botUserId`, return a drop with
    guard `actor:self`. Do not write the inequality the other way round: an optional-chained
    id compared against the bot id evaluates true for a null actor and passes the event
    straight through, which is the exact anti-pattern 03-RESEARCH names. Always populate
    `actorType` in the returned object, including on pass, so the receiver can log the
    observed discriminant — assumption A6 (that a personal-API-key bot appears as the user
    variant) is unsettled, and this field is how one real delivery settles it.

    Layer 2 — invisible marker (D-06, D-07). When `payload.type` is `Comment`, call
    `isBotAuthoredBody(payload.data.body)` imported from the `src/domain/` barrel and
    return a drop with guard `marker:bot-authored`. Import `BOT_COMMENT_MARKER_PREFIX` from
    the same barrel for the diagnostic field only. Do not declare, re-export or re-derive
    either symbol, and do not create `src/shared/markers.ts`: Phase 1 owns these and
    Phase 5 imports the same file. `QUESTION_MARKER_PREFIX` is not needed by ingress — a
    question comment is a bot comment and the predicate already covers it. Guard the body
    read for the non-Comment case rather than assuming the field exists.

    Layer 3 — self-write suppression. Keep a module-level `Map<string, number>` keyed
    `${entityType}:${entityId}`. `noteSelfWrite` stamps `Date.now()` and, in the same call,
    deletes entries older than the window so the map cannot grow without bound. The guard
    drops when a stamp exists and is within `SELF_WRITE_SUPPRESSION_MS`. This is a hint and
    never correctness — it is in-process only, by design, because the daemon is a single
    process. Say so in a comment.

    Layer 4 (delivery-ID uniqueness) is not in this file. It needs the request header and
    the Store and lives in plan 03-05's receiver. Note that in the module header so nobody
    reads three layers and concludes D-06 was under-built.

    The counter (D-09, ROADMAP criterion 4): a module-level plain object keyed by guard
    name, incremented by `incSelfEventDrop`, exported read-only. No metrics dependency and
    no metrics port — this is a single-process daemon and a plain counter is the whole
    requirement. Record the export in `03-SUMMARY.md` so Phase 7 can surface it.

    Every drop path returns its guard name; the receiver does the logging so that the
    delivery id can be attached. Record `noteSelfWrite` in `03-SUMMARY.md` under
    `Contract additions requested` — Phase 5 must call it after every Linear write, and
    until that wiring lands layer 3 is dead code that the per-guard counter will show as
    permanently zero.

    Keep every trap reference in a comment that occupies its own line; the verify gate
    strips whole-line comments but not trailing ones.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

Two documents describe `src/domain/`. They disagree, and the resolution is not negotiable:

1. **`01-CONTEXT.md` ADDENDUM is binding text.** Where it names something — the nine state
   literals, the five table names, the config root, the `Config` type name, the six module
   paths — that name wins.
2. **`research/ARCHITECTURE.md` § Interface Contracts is the contract wherever the ADDENDUM
   is silent.** It is the only other document the parallel executors have. Transcribe its
   identifiers verbatim. Do not rename anything it names, ever. Additions are safe; renames
   break seven branches at the final merge.

Concretely for this plan: ARCHITECTURE.md's state table uses an older nine-name vocabulary
(`claimed`, `worktree_ready`, `agent_running`, `done`, `abandoned`). Those names are DEAD.
The mapping is: `claimed` and `worktree_ready` both collapse into `preparing`; `agent_running`
becomes `running`; `done` becomes `delivered` and gains a sibling `partial`; `abandoned`
becomes `cancelled`. Its `Trigger` union names, however, are NOT superseded — keep all eleven
of them exactly as written.
</contract_precedence>

**types.ts — add three readonly classification arrays** (D-02, ROADMAP success criterion 3):
`TERMINAL` is delivered, partial, failed, cancelled. `HOLDS_SLOT` is preparing, running,
delivering — and nothing else; the awaiting-answer state is deliberately absent and this
absence is what makes hours-long human waits affordable on a three-slot laptop, so say that in
a comment on the declaration. `HAS_CHILD` is running, alone: the Q&A design exits the child
process before parking the run, so a parked run has no live process any more than it has a
slot. Keep `HOLDS_SLOT` as the exported name — ARCHITECTURE.md names it and parallel layers
import it.

**state-machine.ts — the transition table**, as a const record from state to a partial record
of trigger to next state. Entries, exhaustively (D-01, D-05):

- from queued: claim leads to preparing; cancel leads to cancelled; error leads to failed.
- from preparing: the worktree-ready trigger is a self-transition back to preparing (it is a
  real milestone worth an event row even though the state is unchanged — the older contract
  had two states here and collapsing them must not lose the event); spawned leads to running;
  error leads to failed; requeue leads back to queued; cancel leads to cancelled.
- from running: the needs-input trigger leads to the awaiting-answer state; agent-complete
  leads to delivering; error leads to failed; requeue leads back to queued (restart recovery —
  every such row found at boot is a crash artefact, never a live handle); cancel leads to
  cancelled.
- from the awaiting-answer state: answered leads to running; timed-out leads to running (the
  deadline resumes with the agent's own stated assumption); cancel leads to cancelled; error
  leads to failed (question rounds exhausted, or past hard expiry).
- from delivering: the delivered trigger leads to delivered; a new twelfth trigger named
  `delivered_partial` leads to partial; error leads to failed; cancel leads to cancelled.
- from failed: requeue leads back to queued. This is the one documented exception to
  terminal states never transitioning.
- delivered, partial and cancelled have no outgoing entries at all.

Add `delivered_partial` to the `Trigger` union. It is the only addition to ARCHITECTURE.md's
eleven; the partial state did not exist in that document and needs a way in.

**Predicates to export**: `holdsSlot(s)`, `hasLiveChild(s)`, `isTerminal(s)`, each a membership
test against the arrays above; `nextState(from, t)` reading the table; `assertTransition(from, t)`
throwing `IllegalTransitionError` on a null result.

**Cancel semantics (D-05)** — a cancel request is accepted from every non-terminal state, but
two of them do not act on it immediately. Export `acceptsCancel(s)`, true for every
non-terminal state, and `cancelIsDeferred(s)`, true for exactly running and delivering. The
transition table above still lists cancel from those two states as legal, so the eventual
transition is legal when the supervisor reaches its checkpoint; `cancelIsDeferred` is what
tells the caller to set the run's cancel-requested flag now rather than transitioning now.
The reason is that a pushed branch cannot be un-pushed, so an instant transition would lie
about what happened. Put that sentence in a comment — Phase 6 owns the supervisor and will
read this file, not this plan.

**Parent derivation (D-04)** — export `deriveParentState(children: readonly RunState[]): RunState`.
A ticket-level parent run stores no state of its own; its status is computed so that parent and
children can never disagree, which is the exact bug that would let one repo's failure discard
another repo's already-shipped pull request (DELV-07). Precedence, in order: an empty list or an
all-queued list yields queued; any non-terminal child yields running; all children delivered
yields delivered; any child delivered or partial yields partial (a shipped PR is never
discarded by a sibling's failure); any child failed yields failed; otherwise cancelled.

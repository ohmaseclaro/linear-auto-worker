    Export `async function discoverRepos(rootDir: string): Promise<DiscoveredRepo[]>` implemented

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator terminal → wizard process | The operator types a directory path and reads check output; both directions are local and already-trusted (single-operator tool) |
| Wizard process → local filesystem | `repo-discovery.ts` walks a directory tree the operator names; the tree's *contents* (symlinks, permissions, depth) are not fully controlled by the operator if it's a shared or synced folder |
| Wizard process → subprocesses (`git`, `gh`, `claude`) | Preflight shells out via `execa`; subprocess stdout/stderr is attacker-shaped only if one of those CLIs itself is compromised, which is out of this plan's scope |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Denial of Service | `repo-discovery.ts` | medium | mitigate | Hard depth-2 cap and symlink-skip prevent unbounded/looping traversal on a large or self-referential directory tree (Task 3) |
| T-08-02 | Tampering | `repo-discovery.ts` | low | mitigate | Per-entry try/catch means one unreadable or adversarial directory entry (e.g. a `.git` named pipe) cannot abort or corrupt the scan of siblings |
| T-08-03 | Information Disclosure | `preflight.ts` | low | accept | Check output (Node version, gh account, RAM) is printed to the operator's own local terminal only, never transmitted; accepted as the tool's normal operating mode |

No new package-manager install task exists in this plan — `execa` is already pinned and sourced in
`research/STACK.md` with an exact npm-registry version; nothing here triggers the package
legitimacy gate.
</threat_model>

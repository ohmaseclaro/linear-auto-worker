<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Wizard process → `TunnelManager`/`WebhookRegistrar` ports | This plan codes against the port interfaces and their domain fakes; the real ngrok/Linear-backed implementations are wired in later by Phase 7, which is also where this boundary becomes live |
| Wizard process → Linear webhook CRUD | `doctorWebhooks` can delete a webhook registration — the one genuinely destructive action anywhere in this phase |
| `~/.linear-auto-worker/config.json` on disk | Read and merged, not just overwritten — a corrupt or hand-edited existing file is untrusted input to `assembleConfig` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-16 | Tampering | `doctorWebhooks` | critical | mitigate | Deletion only ever follows an explicit, per-item `confirm`; reconcile itself never deletes anything outside its own `WEBHOOK_LABEL`-matched entry, and foreign webhooks are only ever reported, matching Pitfall 2's "do NOT auto-delete foreign" guidance exactly |
| T-08-17 | Information Disclosure | `reconcileWebhook` | critical | mitigate | The webhook signing secret returned by `registrar.reconcile()` is never logged or printed by this plan's code — it is handed to the `Store` (owned by Phase 1/2), and this plan's own console output only ever confirms "secret persisted," never the value |
| T-08-18 | Denial of Service | `reconcileWebhook` (auto-disabled case) | medium | mitigate | `doctorWebhooks`/reconcile both check `enabled` on the matched webhook and re-enable it, so an auto-disabled registration does not leave the operator with a silently-dead setup |
| T-08-19 | Tampering | `assembleConfig` (merge against untrusted existing file) | medium | mitigate | `assembleConfig` only ever reads fields it recognizes from the existing `Config` shape; an unexpected/malformed existing file causes the merge to fall back to treating unresolvable fields as absent (defaults apply) rather than propagating garbage into the newly written file |
| T-08-20 | Tampering | Reconcile-by-URL (rejected alternative) | high | mitigate | Explicitly rejected in favor of reconcile-by-label (see Task 2's behavior spec) — matching by the ephemeral, per-boot-changing URL would never find "our" prior webhook and would silently accumulate duplicates every run (Pitfall 2's exact failure mode this whole task exists to prevent) |

No new package-manager install task exists in this plan — `@linear/sdk@93.0.1` is already sourced
in `research/STACK.md`; this plan imports domain ports/fakes only, no new runtime dependency.
</threat_model>

  <files>src/cli/wizard/register.ts, src/cli/wizard/register.test.ts</files>
  <behavior>

      the tunnel (`tunnel.open(port)`), then calls `registrar.reconcile(publicUrl)`, which — per
      its port contract — is idempotent create-or-update **by a fixed label constant**

      publicUrl }` on success.
    - Any failure (tunnel open fails — e.g. bad/missing authtoken per TUN-03 — or the registrar
      call fails, e.g. non-admin key slipping through) is caught and converted into the same
      `SafetyWarning`-shaped result used elsewhere in this phase (never an uncaught rejection); the
      wizard prints the failure and does *not* claim setup finished.
    - `doctorWebhooks(linearClient)` (the `--doctor` path, Pitfall 2's explicit recommendation for
      Component A): lists all webhooks (paginated — do not trust the 50-item default), reports

      never a blanket delete. Webhooks matching `WEBHOOK_LABEL` but disabled are re-enabled
      automatically (Linear "might" auto-disable a persistently-unresponsive webhook and it "must
      be re-enabled manually" — this is the boot-reconcile behavior `register.ts`'s tests should
      also cover, since Phase 3's real registrar will reuse the same contract).

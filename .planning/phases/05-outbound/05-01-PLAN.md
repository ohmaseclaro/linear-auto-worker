<objective>
Build the one typed Linear facade every outbound Linear call in the system passes through:
authentication via `@linear/sdk`'s own constructor form, rate-limit detection keyed on the
GraphQL error extension code (never HTTP status), per-team workflow-state resolution cached
on the instance, comment threading, and paginated webhook CRUD for Phase 3's registrar to
consume at integration.

Purpose: INTK-04 and OPS-03 both live here, and every later phase (3's registrar, 6's
RunEngine, this phase's own Notifier in 05-02) is expected to be wired to this single module
at the Phase 7 integration gate rather than each hand-rolling `@linear/sdk` calls.
Output: `src/outbound/linear-client.ts` (interface + implementation) and
`src/outbound/rate-limit.ts` (pure helpers), each with a test file.

Note for the executor: this branch has no `node_modules` and no build step (this milestone
run defers all typecheck/test/build to a single end-of-milestone integration gate — see
RUSH constraints in the orchestrator's brief). Every `<verify>` below is a static/structural
grep check, not a real test run. Write the test files completely and correctly; do not
attempt to execute them.
</objective>

Returns false for an error object that only carries a numeric transport status field with no extensions.code at all — proving detection never keys off a status code (TRAPS.md T7).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker process → Linear GraphQL API | Outbound authenticated call carrying the personal API key; response is at-least-trusted vendor data but its error/response objects may carry sensitive transport metadata |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Denial of Service | linear-client.ts (rate-limit wrapper) | high | mitigate | Detect exclusively via the GraphQL error's `extensions.code === 'RATELIMITED'` (never a transport status code — TRAPS.md T7); honor `X-RateLimit-Requests-Reset` (epoch ms) via `computeBackoffMs`; the facade never retries blindly or loops on its own. |
| T-05-02 | Information Disclosure | linear-client.ts (call() error path) | medium | mitigate | Never log a raw SDK error or response object — it can carry the Authorization header or the full query text. Log only the extracted, allow-listed `waitMs`/`complexity` fields. |
| T-05-03 | Spoofing | linear-client.ts (auth construction) | low | accept | The SDK's own `{ apiKey }` constructor form sets the correct no-prefix Authorization header; not hand-rolling a fetch removes the class of bug where a stray Bearer prefix silently breaks every call, so no further mitigation is required. |

</threat_model>

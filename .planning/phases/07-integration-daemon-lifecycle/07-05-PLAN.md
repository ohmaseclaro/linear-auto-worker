<objective>
Complete the daemon lifecycle: the rest of the ordered boot, and the shutdown that undoes
it in reverse.

Two orderings in this plan are load-bearing rather than tidy. The server binds before the
tunnel opens (07-CONTEXT D-02) because a live public URL backed by nothing answers a
gateway error, Linear counts that as a failed delivery, and it has only three retries
before the webhook is auto-disabled. And shutdown runs backwards (07-CONTEXT D-03) because
closing the tunnel while children are still writing, or closing the store before marking
what was in flight, produces exactly the zombie run with a stuck In Progress ticket that
OPS-01 exists to forbid.

Purpose: HOOK-01 and OPS-05, the two requirements this phase owns outright.
Output: a daemon that starts correctly and stops correctly, plus the lifecycle test file.
</objective>

<task type="auto">
  <name>Task 2: Shutdown in reverse boot order, on SIGINT and SIGTERM</name>
  <files>src/cli/daemon.ts, src/cli/index.ts, scripts/boot-smoke.ts</files>
  <read_first>07-CONTEXT D-03; 04-CONTEXT D-09 and D-10; 06-CONTEXT D-07 and D-08</read_first>
  <action>
    Write one idempotent `shutdown(reason)` on the daemon handle and install it on both
    SIGINT and SIGTERM. Sequence, which is the boot sequence run backwards:

      1. pause the scheduler so nothing new is claimed
      2. kill spawned children by process group. The child was spawned detached, so signal
         the negative pid — signalling the child alone orphans the agent's own shell
         subprocesses, which then survive the daemon and keep writing into a worktree
         nothing owns (04-CONTEXT D-09). Escalate through SIGINT, then SIGTERM, then
         SIGKILL, with a grace window between each; the first signal leaves the agent
         session resumable, which the later ones do not (04-CONTEXT D-10)
      3. disable the webhook, best effort and time-boxed — polite rather than required. It
         stops Linear burning retries against a URL that is about to vanish. A failure
         here is logged and skipped, never fatal during a shutdown
      4. close the tunnel
      5. close the HTTP server
      6. mark every run still in a non-terminal state with a shutdown reason, leaving its
         state in place. The next boot applies the per-state recovery rules — queued and
         preparing requeue because nothing was spent, running and delivering fail with a
         diagnosis because an agent session and a partial push cannot be safely resumed
         blind, and awaiting_answer simply persists because its deadline is data in SQLite
         (06-CONTEXT D-07). Do not attempt a blind resume here: re-running a run whose
         branch was already pushed produces a second pull request for work that shipped
      7. close the store

    Make it idempotent — a handler that runs twice must not double-signal a process group
    whose pid may have been reused. A second signal arriving while a shutdown is already
    in progress escalates to an immediate exit rather than being swallowed, so an operator
    pressing the interrupt twice gets what they asked for.

    Have the smoke call shutdown and assert three things: the bound port refuses
    connections afterwards, a second shutdown call resolves without error, and a run left
    non-terminal carries a shutdown reason.
  </action>

  </verify>
  <done>SIGINT and SIGTERM both run one idempotent reverse-order shutdown that kills children by process group with escalating signals, disables the webhook best-effort, closes tunnel then server, marks in-flight runs with a shutdown reason, and closes the store; the smoke proves the port is closed and a second call is safe.</done>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public tunnel URL → local receiver | The tunnel exposes a loopback port to the internet for the daemon's lifetime |
| daemon → spawned process tree | Children hold the operator's shell and outlive a naive kill |
| Linear API → registrar | Webhook reconciliation mutates workspace configuration with an admin-scoped key |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-20 | Denial of service | Tunnel live before the bind | high | mitigate | Boot order asserted from both sides — the stub probes the port, the daemon asserts the receiver reports accepting before entering tunnel open (HOOK-01) |
| T-07-21 | Elevation of privilege | Orphaned agent grandchildren after shutdown | high | mitigate | Kill by negative pid with escalating signals; the lifecycle test spawns a real grandchild and asserts it is gone (04-CONTEXT D-09, D-10) |
| T-07-22 | Tampering | Webhook secret persisted separately from the webhook id | high | mitigate | Both written in one transaction during reconcile; a crash cannot leave a live webhook whose signatures cannot be verified |
| T-07-23 | Denial of service | Webhook auto-disabled by repeated delivery failure | medium | mitigate | Reconcile carries an explicit re-enable path, and shutdown disables the webhook best-effort so a dying URL stops burning retries (03-CONTEXT D-02) |
| T-07-24 | Repudiation | Run stranded non-terminal with a started ticket | high | mitigate | Shutdown marks every in-flight run with a reason and the next boot applies per-state recovery; the lifecycle test asserts no zombie remains (OPS-01) |
| T-07-25 | Information disclosure | ngrok authtoken in logs during tunnel failure | medium | mitigate | The token is passed explicitly to the SDK and is on the logger's redaction list at the sink (02-CONTEXT D-05) |
| T-07-26 | Tampering | Blind resume of a run whose branch was already pushed | high | accept | Deliberately not resumed — running and delivering fail with a diagnosis and leave the branch for the operator (06-CONTEXT D-07, D-13); the cost is a manual restart, the alternative is a duplicate pull request |

    least one mapped repository has a remote and a branch-protected default branch. Then:
    start the daemon, watch for the line reporting the reconciled webhook URL, assign a
    real issue in a mapped project to the bot, and observe — the acknowledgement comment
    and the move to In Progress inside ten seconds, milestone comments as the run
    progresses, and finally a draft pull request whose URL appears in the Linear comment,
    in Slack if the mapping has a webhook, and in the log. Give the operator the exact
    commands to read the log lines for one run id and to confirm no secret appears in the
    logfile.

    Criterion 5, question survival. Assign an issue whose description is deliberately
    underspecified so the agent has a genuine reason to ask. Wait for the question comment.
    Stop the daemon with an interrupt and confirm from the database that the run sits in
    `awaiting_answer` with its deadline intact. Restart. Reply in the thread on the question
    comment. Observe the run resume on the same session and reach a pull request. Then
    repeat once replying in the main comment box instead of the thread, because that is the
    mistake everyone makes and the top-level fallback is what stops it looking like the bot
    is broken.

    For each criterion give an expected-result line and a "what it means if this fails"
    line naming the most likely cause, so a failure produces a report rather than a
    shrug. Close with the two things known to be checkable only here — that a real signed
    delivery from Linear verifies against the locally generated secret, and that the
    reconciled webhook survives a restart without accumulating a duplicate registration.

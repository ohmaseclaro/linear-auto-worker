<objective>
The tracer for Phase 2: one path from a config file on disk to an open, migrated SQLite
handle to a logger that cannot leak what it was given, wired together in `loadFoundation()`.
Then the config side is filled out to its full validated shape.

a database that blocks the event loop, or a secret that leaked into a log line. Proving the
three pieces wire together before either the store's full CRUD surface or the logger's
redaction edge cases are hardened (plan 02) catches an architectural mistake in this plan's
own commit, not spread across three later ones.
Output: `loadFoundation()` plus a fully validated `Config` loader; `sqlite-store.ts`'s CRUD
surface is plan 02's job, not this one's.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Local filesystem (`config.json`, `.env`) -> Config loader | Locally-authored files crossing into a typed schema; a malformed or oversized file must not crash or hang the daemon |
| Config secrets -> Logger sink | The exact boundary D-05 exists to hold: a secret value must never cross into anything written to stdout |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information Disclosure | logger.ts | critical | mitigate | Redaction is one sink-level serializer — a single `pino()` call site — that scrubs both key-name patterns and known secret values, never a per-call-site convention that can be forgotten once |
| T-02-02 | Tampering | config.ts (`.env`) | medium | mitigate | `loadSecrets()` reads the file's mode and throws rather than proceeding when it is not exactly `0600` |
| T-02-03 | Denial of Service | config.ts | low | mitigate | `ConfigSchema.safeParse()` never throws on malformed input; string and array fields carry explicit bounds so a pathological `config.json` cannot force unbounded allocation |
| T-02-04 | Tampering | store/db.ts | medium | mitigate | WAL mode and an explicit busy timeout are set before any statement runs, so concurrent writers retry through SQLite's own locking instead of racing each other |
| T-02-SC | Tampering | npm install (zod, better-sqlite3, pino) | high | mitigate | `package.json` pins the exact versions STACK.md verified against the npm registry; no install runs in this plan, and Phase 7 owns the legitimacy audit before `npm install` executes on the merged tree |
</threat_model>
